# TableScan Local 0.7 — адаптация к почерку без ручного обучения

Статус: реализовано; адаптация предлагает варианты для ручного подтверждения.

## Цель

Уменьшить ошибки между визуально похожими рукописными цифрами (`1/2/7`, `4/9`
и другими) без жёсткой таблицы замен, без угадывания по допустимому диапазону и
без требования заранее обучать программу почерку пользователя. Качество важнее
фиксированного лимита времени; дополнительный этап не должен сокращать полный
OCR-каскад.

## Решение

1. Первый проход сохраняет все прежние источники: три локальные OCR-модели,
   ограниченный CTC-поиск, геометрию знаков, варианты выреза и независимую
   EMNIST-проверку.
2. Из устойчивых значений одной страницы строится временный профиль почерка.
   Не используются исправления пользователя, исключённые строки, слабые ответы
   или ответы с конфликтом моделей.
3. Для каждого класса цифры нужны образцы из разных ячеек. Повторение цифры в
   одной ячейке не создаёт фиктивное большинство, а проверяемая ячейка исключена
   из собственных образцов.
4. Второй проход сравнивает сегментированные знаки только с теми полными
   строками, которые уже присутствуют среди OCR-кандидатов, имеют ту же
   структуру целой/дробной части и разрешены правилом шаблона.
5. При не менее чем трёх независимых образцах, достаточном сходстве и согласии
   отдельной модели программа показывает конкретный альтернативный вариант, но
   не переписывает значение автоматически. Проверка на реальных страницах
   показала, что два этих источника всё ещё способны разделить одну ошибку.
6. При более слабом противоречии ответ также не меняется, но становится спорным.
   Уверенное совпадение с исходным ответом является только аудиторским сигналом
   и не увеличивает заявленную вероятность точности.

## Безопасность

- Профиль существует только во время обработки страницы и не является базой
  биометрических или пользовательских данных.
- Эталонные ответы и файлы проверки не участвуют в распознавании.
- Ограничения шаблона не создают цифры и не выбирают одну визуальную форму из
  двух допустимых.
- Старый сильный голос по сходству повторённых цифр внутри одной ячейки удалён.
- Исходное чтение, альтернативы и доказательства адаптации сохраняются в Audit.

## Производительность

Полный первый проход не сокращается. Второй проход использует компактные HOG-
признаки уже сохранённых вырезов и повторную проверку кандидатов компактной
моделью цифр; полный OCR-каскад не повторяется. Поэтому
его ожидаемая стоимость мала относительно OCR; измеряется отдельно на полном
локальном наборе.

Измеренный прогон на отложенной локальной выборке: основной OCR — 221,69 с,
адаптивный проход — 1,30 с (около 0,6% дополнительного времени). Получено
54/57 правильных значений как до, так и после адаптации; автоматических замен и
регрессий не было. На отдельной выборке разработки результат также не ухудшился
(52/59), но исправлений не добавилось. Поэтому версия 0.7 не заявляет измеренный
рост точности на этих двух небольших выборках: её результат — безопасный новый
источник доказательств и инфраструктура для последующего улучшения, а не
искусственно завышенное число исправлений за счёт рискованных эвристик.

## Критерии готовности

- Нет специальных правил или весов для конкретных пар цифр.
- Ячейка не подтверждает сама себя; нужны независимые ячейки.
- Одного или двух образцов недостаточно для автоматической смены кандидата.
- Профиль не меняет формат числа и не создаёт отсутствующий OCR-кандидат.
- Адаптация не переписывает значение: предложенный вариант требует явного
  подтверждения; уверенное согласие с исходным ответом не создаёт спор.
- Связанные подсветки, пустые/зачёркнутые строки и оба вида Excel-экспорта не
  регрессируют.
- Пройдены модульные тесты, локальная контрольная выборка и самопроверка
  собранного приложения.
