# Правила значений — версия 0.7.0

## Как настроить

1. Откройте PDF и проверьте сетку на вкладке Grid. Заголовки над таблицей не
   считаются её строками: в таком случае Header rows = 0.
2. Перейдите на вкладку **Правила ячеек** и нажмите **Обвести ячейки на фото**.
   Протяните прямоугольник от первой до последней нужной ячейки. Выделение
   привязывается к клеткам сетки; номера строк и столбцов можно уточнить в окне.
   Для одиночной ячейки обведите её внутреннюю область. Есть также кнопки
   **Все измерения**, **Строка…**, **Столбец…**.
3. Выберите готовый формат, например **Дробь 0–100, один знак (34,4)**, или
   настройте свой. «Разрешено от / до» — включительные границы. Пустая граница
   означает отсутствие ограничения с этой стороны.
4. При необходимости задайте список разрешённых значений, разделяя их
   точкой с запятой: `0; 1; 2; 3`. Запятые внутри чисел допустимы.
5. Нажмите **Применить правило**. Область появится на изображении и в списке.
   Правило сохранится в шаблоне вместе с сеткой и обычными полями документа.
6. Вернитесь в Grid и нажмите **Save grid and continue**, чтобы распознать
   документ с новыми правилами. Старые подтверждённые результаты не
   переинтерпретируются автоматически.

Для базового правила целого столбца используйте вкладку **Столбцы → Формат и
допустимые значения…**. Прямоугольное правило имеет приоритет над столбцом.
Если прямоугольники пересекаются, действует последнее правило в списке.
Изменённое правило перемещается в конец списка. Отсчёт адресов начинается с 1
и включает строки заголовков. Игнорируемые столбцы остаются игнорируемыми.

## Что означает «разрешено», а что — «обычно»

| Настройка | Поведение |
|---|---|
| Целое / десятичное / текст | Проверяет вид записи и выбирает подходящие прочтения OCR |
| Ровно один дробный знак | `34.4` и `34,4` подходят; `344` и `34.44` не подходят |
| Разрешено 0–100 | `100.0` допустимо; `100.1` — конфликт правила |
| Обычно 20–60 | `90.0` остаётся `90.0`, но выделяется как необычное |
| Предпочитать обычный диапазон | Выбирает первый реально прочитанный OCR-вариант внутри 20–60, сохраняет исходник и требует сверки |
| Только `0; 1; 2` | Другой ответ не принимается; значение из списка не выдумывается |
| Предлагать разделитель | При отсутствии подходящего прочтения может предложить `344 → 34.4`, с обязательной сверкой |

Программа сначала выбирает подходящий вариант из результатов моделей.
Это ограничение выбора OCR-ответа, **не переобучение модели** и не гарантия
правильного чтения каждой цифры.

Предложение пропущенного разделителя включается явно (в готовых дробных
форматах флажок включён и виден). Оно лишь вставляет точку между уже
распознанными цифрами. Оно не удаляет первую единицу, не превращает буквы в
цифры и не передвигает уже прочитанный разделитель. `4115` не превращается в
`41.5` по такому правилу. Если среди OCR-ответов есть `415`, программа может
предложить `41.5` именно из этого альтернативного прочтения. Если допустимы
несколько разных предположений, исходный спорный ответ остаётся видимым.

## Проверка и экспорт

В Review показаны применённое правило, исходный ответ и альтернативы. Число,
которое нарушает жёсткое правило, нельзя подтвердить кнопкой Confirm. Сначала
исправьте значение либо поправьте правило и повторите распознавание. Если
само правило ошибочно, не подгоняйте под него реальное измерение.

Обычный диапазон не запрещает подтверждать реальные выбросы. По умолчанию он
только предупреждает; предпочтение кандидата включается отдельным флажком.
Все числовые
предложения требуют сверки с оригиналом. Экспорт дополнительно проверяет
жёсткие ограничения; в Audit сохраняется применённое правило вместе с
исходным ответом и вариантами. Настройки не отправляются на сервер.

Правила прямоугольников в этой версии относятся к клеткам **основной сетки**.
Для отдельных областей вне сетки вкладка Fields сохраняет прежние настройки
типа значения; дополнительные диапазоны этой версии на них не распространяются.

## Ограничения

Правила уменьшают число структурно невозможных ответов, но не заменяют чтение
изображения. Например, оба варианта `47.2` и `97.2` могут соответствовать одному
широкому диапазону. Такие различия должны разрешаться распознавателями либо
оставаться для ручной сверки.

Старые шаблоны открываются без изменения ранее сохранённых результатов. После
изменения правил исходный документ следует запустить заново: программа не
переписывает подтверждённые задания скрыто.
